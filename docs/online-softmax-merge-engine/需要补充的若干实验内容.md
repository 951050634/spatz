# Online Softmax Merge Engine：补充实验可行性与执行边界

> 审计基线：2026-07-15，分支
> `feature/online-softmax-merge-engine`，审计时 HEAD 为 `136da62`。
> 本文档覆盖原有“六项必做实验规划”，并将实验划分为：
> **当前可执行**、**需要实现支持**、**外部环境条件项**。
>
> 本文中的“可执行”只表示当前仓库和本机工具能够产生对应数据；
> 不代表这些数据天然足以支持 ASIC 面积、频率、功耗或能耗结论。

---

## 0. 结论先行

### 0.1 当前环境下可以完成的实验

以下实验能够在现有 Verilator、Spatz 软件工具链和开源综合工具基础上完成：

1. **逐级软件 baseline 与 Full SMU 周期对比**：
   当前已有 RTL-aligned scalar reference 和 Full SMU 路径；补齐 RVV 路径后，
   可形成主要性能证据链。
2. **规模、启动开销、break-even 和 TCDM 拥塞实验**：
   需要先把 benchmark 从固定 `MAX_N/MAX_D` 缓冲区改为按 `(N,D)` 紧凑分配，
   然后使用单 case/批处理方式运行。
3. **SMU 内部阶段周期分解**：
   可直接按 FSM 状态统计 scalar 阶段与 vector 阶段，无需先修改硬件接口。
4. **core–SMU 并发及 bank phase 扫描**：
   SMU 是独立 TCDM master，core 在发起后可以继续执行，因此该实验可行。
5. **Yosys generic resource proxy**：
   本机 Yosys 可通过 `yosys -m slang` 解析当前 SystemVerilog；加入固定类型的
   synthesis-only wrapper 后，可报告 generic cell、寄存器、乘法器位宽和
   ROM/LUT inference 等逻辑资源代理。
6. **RTL VCD toggle proxy**：
   Verilator 可生成 VCD，可报告 kernel 窗口内的 toggle、toggle/cycle 和
   toggle/element，但不能将其直接换算为 mW 或 pJ。

### 0.2 当前环境下不能形成可信物理结论的实验

当前机器没有 OpenROAD/OpenSTA、Design Compiler/Genus/PrimeTime、
VCS/Questa/Vivado，也没有目标 ASIC liberty、PDK、LEF、标准单元数据库和
已定义的工艺角。仓库中仅有普通功能 SDC：

```text
hw/system/spatz_cluster/lint/sdc/func.sdc
```

因此，**当前不得报告或推断**：

- ASIC 面积或面积增量（`µm²`）；
- cluster post-layout 面积 overhead；
- `Fmax`、MHz、时序收敛或真实 critical path；
- mW、动态/静态功耗；
- pJ/merge、pJ/element 或真实能效；
- 带布局布线寄生参数的功耗和能耗。

开源 generic cell count 和 RTL toggle 可以作为结构复杂度、活动度代理，
但必须明确标注为 **proxy**，不得替代 ASIC PPA 数据。

### 0.3 需要先实现、再运行的实验

以下项目不是当前“直接可跑”的现成实验，但可在本仓库内补齐：

- target scalar `expf` baseline 及 `expf + RVV` baseline；
- scalar-only SMU 消融模式；
- 按 `(N,D)` 紧凑分配的 benchmark 和统一批处理测量框架；
- FSM/busy-cycle 低扰动计数器；
- 必要时由 `SPATZ_STATUS`/probe 控制的 VCD trace gating；
- 固定的 Yosys Slang wrapper、综合脚本和结果解析脚本。

## 1. 审计到的固定环境与硬边界

### 1.1 主实验必须固定的 cluster 配置

配置来源：

```text
hw/system/spatz_cluster/cfg/spatz_cluster.default.dram.hjson
```

所有主结果必须固定并记录：

| 配置项 | 固定值 |
| --- | ---: |
| TCDM 容量 | 128 KiB |
| TCDM banks | 16 |
| cores | 2 |
| VLEN | 512 bit |
| Spatz FPU | 4 |
| TCDM 数据宽度 | 64 bit |
| misalign | false |

不要为了获得更好结果直接修改默认 HJSON。若需要对比其他配置，应通过
`CFG=...` 选择单独配置，并在结果中把它标为独立实验，而不是与主实验混合。

TCDM bank selector 使用：

```systemverilog
addr[ByteOffset +: SelWidth]
```

在 64-bit bank 粒度、16 banks 下，bank phase 由 `addr[6:3]` 决定。
因此并发实验应扫描相对 base offset，而不能笼统声称两个跨 bank streaming
workload 被放入“完全不同的 bank”。

### 1.2 当前工具可用性

已在当前环境发现：

```text
Verilator 5.049
Yosys 0.66+4
Icarus Verilog 14.0
nextpnr-ecp5 0.10...
hw/system/spatz_cluster/bin/spatz_cluster.vlt
```

关键约束如下：

- Yosys 内建 `read_verilog -sv` 不能直接解析当前 SMU 的 package import 和
  parameterized struct 类型；必须使用 `yosys -m slang`。
- OSS CAD Suite 中存在 `share/yosys/plugins/slang.so`，已经完成解析与
  generic-synthesis smoke test。
- 完整 `online_merge_update_engine` 需要 synthesis-only wrapper 固定 TCDM
  request/response struct 类型；正式实验不能依赖 `/tmp` 中的临时 wrapper。
- `nextpnr-ecp5` 虽然存在，但当前没有固定 FPGA device、package、时钟与 IO
  约束，因此暂时不能把其 P&R/Fmax 当作论文结果。
- RISC-V 工具链中存在 `libm.a`，但当前 benchmark CMake 没有链接 libm，
  仓库现有 benchmark 也没有 target-side `expf` 路径。

一次审计 smoke test 对完整 SMU 得到约 98,538 个 bit-blasted generic cells 和
约 628 个 FF-like cells。该值高度依赖 techmap、宽乘法展开和临时 wrapper，
**只证明流程可运行，禁止直接写入论文面积表或与物理面积对应**。

### 1.3 当前仿真成本

已有 CTest 日志显示，完整 online-softmax-merge 测试曾耗时：

```text
1123.18 s，约 18.7 min
```

因此，规模矩阵、seed 扫描和重复测量不能对每个点重新运行整个测试套件。
必须提供只包含单一 workload 的 benchmark，或支持命令行/编译参数选择单 case
的批处理 runner。

默认执行预算：

- 单 case wall-clock 上限 30 分钟；
- 大规模 anchor 可放宽到 60 分钟；
- 超时必须记录为 `timeout`，不得只删除失败点；
- 长矩阵先完成 smoke/anchor，再展开全量，避免数小时后才发现测量口径错误。

## 2. 所有实验共用的边界和测量协议

### 2.1 benchmark 缓冲区与 TCDM 容量

当前文件：

```text
sw/spatzBenchmarks/online-softmax-merge/main.c
```

包含固定边界：

```c
#define MAX_N 16
#define MAX_D 64
```

当前 `smu_buffers_t` 约为：

```text
29184 bytes = 28.5 KiB
```

这只是当前 benchmark 的静态分配边界，不是 SMU 硬件上限。规模实验前必须：

1. 按实际 `(N,D)` 紧凑分配或生成 buffer；
2. 顺序复用仅用于中间检查的输出；
3. 避免 packed、error-path 和 reference 全部按最大尺寸常驻；
4. 记录每个 case 的静态/动态 TCDM footprint；
5. 在运行前检查容量，容量不满足时返回 `capacity_skip`，不得发生静默覆盖。

三态 `old/tile/out` 的最小数据 footprint 为：

```text
N * (24 + 12D) bytes
```

若再保留一份 reference 输出，则总 footprint 约为：

```text
N * (32 + 16D) bytes
```

主实验把工作集上限设为 TCDM 的 70%：

```text
0.7 * 128 KiB = 91750 bytes，约 89.6 KiB
```

剩余约 38.4 KiB 留给 runtime、stack、元数据和对齐。理论上，在包含 reference
footprint 时：

```text
D=64：N 上限约 86
N=8 ：D 上限约 714
```

这些只用于容量预检查，**不是强制必测规模**。

### 2.2 地址、stride 与 alias 规则

统一规则：

- 所有 base address 至少 4-byte 对齐；
- 主性能实验使用 packed layout：`stride = 4D`；
- `stride = 0` 只作为“等价 packed 语义”的功能测试；
- 非零 stride 必须为 4 的倍数，并默认满足 `stride >= 4D`；
- 主实验禁止输入和输出 alias；
- 若要研究 alias，必须单列功能实验并先定义硬件行为，不能混入性能结果；
- 同一横向比较中的实现必须使用相同 base、stride 和数据布局。

### 2.3 数值输入域

当前 RTL 的可信功能域：

- `m_old/m_tile`：finite normal 或 zero，可正可负；
- `l_old/l_tile`：非负 finite normal 或 zero，但不能同时为零；
- exp 近似设计区间为 `[-8,0]`；
- 正输入饱和到 1，低于 `-8` 饱和到 0；
- 内部路径为 48-bit、32 fractional bits，可视作 Q16.32 类固定点；
- `O` 输入没有完整 IEEE-754 异常处理承诺。

主随机正确性和性能域固定为：

```text
m_old,m_tile ∈ [-4,4]
l_old,l_tile ∈ {0} ∪ [2^-8,8]，且二者不能同时为 0
O_old,O_tile ∈ [-1,1]
```

这使主路径 exp delta 位于 `[-8,0]`，并远离明显的固定点溢出区域。

单独设置功能边界集：

- `m_old == m_tile`；
- delta 恰好为 `-8`；
- delta 小于 `-8`，验证饱和，但不计入主精度统计；
- 仅一个 `l` 为 0；
- 很小但合法的正 `l`；
- 正负混合的 `O`；
- RVV tail 维度；
- NaN、Inf、subnormal 只验证 error/unsupported 策略，不计入性能和主精度数据。

在没有明确定义之前，不承诺 NaN、Inf、subnormal、固定点溢出或中间值回绕的
IEEE-754 等价语义。

### 2.4 正确性口径

保留当前 gate：

```text
abs(got - ref) <= 1e-3 * max(1, abs(ref))
```

每个 case 还必须记录：

- maximum absolute error；
- maximum relative error；
- RMSE；
- bit-equal ratio；
- 首个失败元素及其输入、expected、actual；
- 是否属于主数值域或 unsupported/boundary case。

Host double golden 只用于数值基准，不在 Spatz 周期窗口内执行，也不计入 target
runtime。

### 2.5 周期测量与重复规则

统一周期窗口：

1. 输入初始化、cache/TCDM 填充、正确性检查和打印不计入周期；
2. 首次执行作为 warm-up，不计入统计；
3. 默认测量 5 次；慢速 Verilator case 最少 3 次；
4. 报告中位数，并保留 min/max；
5. 使用 64-bit cycle helper，或明确证明 32-bit `mcycle` 没有回绕；
6. MMIO 配置、启动和必要同步属于 end-to-end 加速器成本，必须计入；
7. 软件和 SMU 必须使用相同输入、CFG、stride、优化等级和测量窗口；
8. 禁止只挑最快一次作为最终结果。

Verilator 周期 speedup 只能称为“同配置下的 cycle/runtime proxy”。在没有 ASIC
或固定 FPGA Fmax 的情况下，不能将 cycle speedup 自动解释为真实 wall-clock
speedup。

### 2.6 最小结果 schema

CSV/JSON 至少包含：

```text
git_commit,cfg_path,cfg_hash,tool_version,implementation,
N,D,stride,seed,repeat,cycles,tcdm_accessed,tcdm_congested,
max_abs,max_rel,rmse,bit_equal_ratio,status
```

并派生：

```text
cycles_per_element = cycles / (N*D)
elements_per_cycle = (N*D) / cycles
congestion_ratio = tcdm_congested / tcdm_accessed
```

所有脚本必须保留失败点，`status` 至少区分：

```text
pass,correctness_fail,timeout,capacity_skip,unsupported,tool_error
```

## 3. 实验一：逐级 Baseline

### 3.1 状态

- `[当前可执行]` G0、B1、B3；
- `[需要实现支持]` B0、B2-F、B2-R；
- `[当前可执行]` 补齐 B2-R 后的统一周期和拥塞比较。

### 3.2 版本定义

| 编号 | 实现 | 数值语义 | 用途 |
| --- | --- | --- | --- |
| G0 | Host double/FP32 golden | 高精度公式 | 仅正确性，不计 target 周期 |
| B0 | Target scalar FP32 + `expf` | 自然 FP32/libm | 自然标量软件 baseline |
| B1 | RTL-aligned scalar | 与 RTL 近似路径对齐 | 同语义 scalar baseline |
| B2-F | scalar `expf` + RVV `O` 更新 | 自然 FP32/libm | 自然 RVV baseline |
| B2-R | RTL-aligned scalar weights + RVV `O` 更新 | RTL-aligned | 主规模、同语义 RVV baseline |
| B3 | Full SMU | RTL 硬件路径 | 被评估方案 |

B0/B2-F 必须显式链接 target newlib/libm，并先做 smoke test，确认 `expf` 没有被
host 预计算、错误替换或因链接设置失败。B2-R 是论文中最重要的同语义高性能
软件 baseline。

### 3.3 RVV 实现边界

B2-F/B2-R 的 `O[D]` 路径应执行：

```text
load O_old
load O_tile
multiply O_old by w_old
fused/non-fused multiply-add O_tile by w_tile
store O_new
```

要求：

- 使用 VLA/tail 语义，不能假定 `D` 是 16 的倍数；
- 不得用只对固定 `D` 生效的手工展开冒充通用 RVV baseline；
- 若 fused 与 non-fused 影响数值结果，应分别记录编译器生成和容差；
- 保存反汇编片段或自动检查，证明目标函数实际产生 RVV 指令；
- B2-F 与 B2-R 分开报告，不把不同 exp/reciprocal 语义混成一个速度结论。

correctness-only RVV tail 集合：

```text
D = {1,7,15,17,31,33,63,65,127}
```

### 3.4 必测规模

最小 anchor：

```text
(1,1)
(8,32)
(16,64)
```

若某个实现（尤其 `expf`）在 Verilator 下过慢，可对 B0/B2-F 仅运行 anchor 和
必要正确性点，但 B1/B2-R/B3 必须覆盖第 5 节的主规模矩阵。

### 3.5 输出与验收

必须输出：

```text
B3 vs B0
B3 vs B1
B3 vs B2-F
B3 vs B2-R
```

验收条件：

1. 所有版本共享输入生成器、buffer layout 和测量 helper；
2. B0/B2-F 相对 G0 满足 FP32 容差；
3. B1/B2-R/B3 满足既定 host correctness gate；
4. RVV tail 点全部通过；
5. 主 headline 使用 **SMU 对最快实测 RVV 实现** 的加速；
6. 现有约 `37.89x` 只能作为特定旧 baseline 的历史结果，不得代替新矩阵。

## 4. 实验二：消融与阶段分解

### 4.1 状态

- `[当前可执行，P0]` Full SMU FSM 阶段周期分解；
- `[当前可执行，P0]` A0/B2-R 与 A2/B3 对比；
- `[需要实现支持，P1]` A1 scalar-only offload。

### 4.2 一级消融：不改接口的 FSM 分解

当前硬件首先应完成以下状态的 cycle breakdown：

```text
scalar part:
  LOAD_SCALAR
  COMPUTE_SCALAR
  COMPUTE_WEIGHT
  STORE_SCALAR

vector part:
  UPDATE_VECTOR

other:
  command/setup/wait/error
```

实现方式可以是：

- 仿真层次化观测 FSM state；或
- 加入仿真计数器；或
- 从 VCD 中按状态信号统计。

必须保证计数总和能与端到端 busy cycles 对齐，并说明是否存在状态重叠。
该实验能够直接回答 scalar nonlinear path 与 vector streaming path 各自占比，
应作为 mandatory ablation，不等待 A1 完成。

### 4.3 二级消融：A0/A1/A2

| 编号 | scalar merge | `O[D]` update | 状态 |
| --- | --- | --- | --- |
| A0 | B2-R 软件 | RVV | 当前路径补齐后可跑 |
| A1 | SMU | RVV | 需要新增 scalar-only mode |
| A2 | SMU | SMU | 当前 Full SMU |

A1 当前不能直接运行：现有 SMU 没有只执行 scalar 的 mode，也没有输出两个权重的
完整路径。推荐的最小扩展为：

1. 新增 `SCALAR_ONLY` mode；
2. 每行写回 `m_new`、`l_new`；
3. 新增 `dst_w` buffer，每行存储
   `{w_tile_fp32, w_old_fp32}`，共 8 bytes；
4. scalar-only 模式不读取或写入 `O`；
5. core 在 SMU 完成后读取权重，并用与 B2-R 相同的 RVV kernel 更新 `O[D]`。

A1 总周期必须包含：

```text
MMIO/command configuration
SMU scalar execution
completion synchronization
weight readback
RVV vector update
```

默认消融使用顺序执行，不允许在 A1 中隐式加入 overlap。若以后研究 overlap，
应另列为并发实验。

A1 与 A2 的存储舍入位置可能不同，因此按 host tolerance 比较，不声称 bit-exact。

### 4.4 必测点与验收

至少使用：

```text
(1,1)
(8,32)
(16,64)
```

输出：

- A0、A1、A2 端到端 cycles；
- A1 对 A0 的收益；
- A2 对 A1 的额外收益；
- 权重写回/读回成本；
- scalar/vector 状态周期占比；
- TCDM accessed、congested 和 congestion ratio。

若时间不足，验收顺序为：

1. 必须完成 FSM breakdown；
2. 必须完成 A0 vs A2；
3. A1 作为 P1 实现，不得伪造“scalar-only”估算柱。

## 5. 实验三：规模、适用范围与 break-even

### 5.1 状态

- `[需要实现支持，P0]` 紧凑 buffer、参数化 runner 和批处理结果输出；
- `[当前可执行，P0]` 完成上述支持后的周期/拥塞矩阵；
- `[可选]` 靠近 TCDM 容量边界的探测点。

### 5.2 强制性能矩阵

固定 `D=64`：

```text
N = {1,2,4,8,16,32}
```

固定 `N=8`：

```text
D = {1,8,16,32,64,128}
```

所有 mandatory case 统一满足：

```text
N * D <= 2048
working_set <= 70% TCDM
```

break-even 小矩阵：

```text
N = {1,2,4,8}
D = {1,8,16,32}
```

可选容量探测：

```text
D=64：N = {48,64,80}
N=8 ：D = {256,512}
```

容量探测必须在运行时打印真实 footprint；不能仅根据 `MAX_N/MAX_D` 判断硬件能力。

### 5.3 分析模型

对 B2-R 和 B3 分别拟合：

```text
C(N,D) = C0 + N * (Cs + D * Cv) + Cstall
```

其中：

- `C0`：命令配置、启动和固定同步成本；
- `Cs`：每行 scalar merge 成本；
- `Cv`：每元素 vector update 成本；
- `Cstall`：TCDM 竞争、流水线停顿等未被理想线性项解释的成本。

必须报告拟合参数、残差和 `R²`，不得只画一条无参数趋势线。
若残差随 `N/D` 呈系统性变化，应结合 `tcdm_congested` 解释，而不是强行宣称
严格线性扩展。

### 5.4 break-even 定义

定义：

```text
C_smu(N,D) <= C_rvv(N,D)
```

对每个实测 `N`，报告满足上式的最小实测 `D`。未测量的 `D` 只能标为模型预测，
不能与直接测量点混合，也不能在样本稀疏时过度插值。

### 5.5 指标和验收

每个 case 至少报告：

```text
cycles
cycles / (N*D)
elements / cycle
tcdm_accessed
tcdm_congested
congestion_ratio
speedup vs B2-R
```

验收条件：

1. 两条固定矩阵全部有状态记录；
2. capacity/timeout/failure 点没有被删除；
3. 给出测得的 break-even 表；
4. 给出模型参数、残差和 `R²`；
5. 能区分固定启动成本、scalar per-row 成本与 vector per-element 成本；
6. 容量结论来自真实 footprint，而不是旧的静态宏。

## 6. 实验四：综合、面积与频率

### 6.1 当前可执行：generic resource proxy

状态：`[当前可执行，P0，但需把临时流程工程化]`。

正式流程必须新增并版本化：

- synthesis-only top/wrapper，固定 TCDM req/rsp 类型；
- `yosys -m slang` 脚本；
- pre-techmap 与 post-techmap 两级统计；
- 按模块解析资源的脚本；
- 工具版本、输入 RTL commit 和脚本 hash。

建议统计：

1. pre-techmap `$mul` 数量及每个乘法器位宽；
2. `$add/$sub/$mux/$compare` 等主要算子数量；
3. FF/register bit 数；
4. memory/ROM/LUT inference；
5. post-techmap generic logic cell proxy；
6. 按以下层级分解：

```text

reciprocal approximation
scalar/FSM/control
vector arithmetic/data path
```

报告标题必须使用“generic resource proxy”或“logic complexity proxy”，不能写成
“ASIC area”。不同 Yosys techmap 版本之间的 cell count 不应直接横向比较。

### 6.2 当前不可执行：可信 ASIC area/Fmax

状态：`[外部环境条件项，P2]`。

开展该实验前，必须固定：

```text
technology / standard-cell library
PVT corner
liberty / LEF / PDK
clock target
clock uncertainty
IO/input delay and output load
synthesis and P&R tool/version
floorplan/utilization/routing constraints
```

1. module-level SMU synthesis；
2. baseline cluster synthesis/P&R；
3. cluster+SMU synthesis/P&R；
4. 在共同目标频率下比较 area/timing；
5. 另列 baseline 与 SMU 版本各自 Fmax；
6. 区分 post-synthesis cell area 与 post-P&R area。

### 6.3 cluster overhead 的正确对照

SMU 初始集成提交为：

```text
957667e [smu] Add online merge engine prototype
```

优先使用 **同一提交/同一 RTL 基线** 下的 `SMU_ENABLE=0/1` 变体。
如果当前没有开关，可把 `957667e^` 当作历史候选，但必须先审计从该提交到当前
版本是否还包含其他 cluster/RTL 变化。

禁止直接用“当前 HEAD - `957667e^`”的全部差值声称是 SMU overhead。
若必须增加开关，开关关闭时应尽量保持非 SMU RTL、约束和构建脚本完全相同。

### 6.4 FPGA proxy 的边界

`nextpnr-ecp5` 仅在以下条件固定后才可作为额外 FPGA proxy：

- device；
- package；
- speed grade；
- top-level pin/clock constraints；
- Yosys/nextpnr 版本和 seed。

FPGA LUT/FF/Fmax 不能替代 ASIC 面积、功耗或频率结果。若论文目标明确是 ASIC，
该项保持 optional，不应消耗 P0 时间。

### 6.5 验收

- exp、reciprocal、完整 SMU 均可综合；
- 生成结构化 generic resource 表；
- 明确列出外部 PPA blocker。

没有真实 library/PDK 时，不要求也不允许生成伪 `µm²`、MHz 或 critical path
结论。

## 7. 实验五：功耗、活动度与能耗

### 7.1 当前可执行：RTL toggle proxy

状态：`[当前可执行，P0]`。

Verilator trace 入口：

```bash
SNITCH_TRACE_FILE=<file>.vcd \
  hw/system/spatz_cluster/bin/spatz_cluster.vlt \
  --trace <benchmark-elf>
```

当前 C++ Verilator wrapper 会 dump 整个模拟过程。可先通过 `SPATZ_STATUS` 或
`cluster_probe` 在 VCD 中定位 kernel 窗口，但这不会减小 VCD 本身。因此：

1. 使用只包含单 workload 的最小 benchmark；
2. 首先只跑 `(1,1)`、`(8,32)`、`(16,64)` 三个代表点；
3. 若 VCD 过大，再实现由 probe/start/done 控制的 C++ trace gating；
4. VCD 只保存在 `work-*` 目录，不提交 Git；
5. 结果中记录 VCD SHA256、commit、CFG hash 和窗口起止 cycle。

可报告：

```text
total signal toggles
toggles / cycle
toggles / (N*D)
hierarchy toggle breakdown
busy-window cycles
```

建议分层：

```text
SMU scalar/exp/reciprocal
SMU vector data path
SMU control/FSM
TCDM-facing request/response signals
core or RVV baseline hierarchy
```

### 7.2 RTL VCD 不能回答的问题

RTL 零延迟 VCD 不包含或不能可靠表达：

- 组合 glitch；
- cell internal power；
- 布线寄生、电容和负载；
- clock tree；
- leakage；
- 电压、工艺角和真实频率影响。

因此，不能给每次 toggle 乘一个任意常数来生成 mW/pJ，也不能把 toggle ratio
直接称为 energy reduction。

### 7.3 外部条件满足后的真实功耗/能耗

状态：`[外部环境条件项，P2]`。

需要 gate-level/post-layout netlist、SDF/寄生、library power model、SAIF/VCD 与
功耗工具。统一定义：

```text
T_busy = busy_cycles / f_clk
E_total = P_active * T_busy
E_incremental = (P_active - P_idle) * T_busy
E_element = E_merge / (N*D)
```

必须同时报告：

- `P_idle`、`P_active`；
- total energy 与 incremental energy；
- busy cycles 和使用的 `f_clk`；
- workload、PVT、library 和 activity window；
- RVV 与 SMU 是否使用相同工艺、corner、频率和输入。

如果 cluster+SMU 与 baseline cluster 的 idle power 不同，论文主文应优先展示
incremental energy，同时保留 total energy，避免隐藏 sidecar 静态成本。

### 7.4 验收

当前环境的验收上限为：

1. 代表点 VCD 可生成；
2. kernel 窗口可重复定位；
3. toggle parser 输出结构化统计；
4. RVV 与 SMU 使用相同输入和窗口定义；
5. 结果明确标注 `RTL toggle proxy`；
6. 真实功耗/能耗保持 blocker，不产生虚构数据。

## 8. 实验六：core–SMU 并发与 TCDM 竞争

### 8.1 状态与实验目的

状态：`[当前可执行，P0，但需新增并发 microbenchmark/低扰动计数]`。

SMU 是独立 TCDM master，core 发起命令后可以继续执行，因此并发实验在架构上
可行。实验需要分别回答：

1. core workload 不访问 TCDM 时，是否能与 SMU 近似完整 overlap；
2. core/RVV 同时 streaming TCDM 时，双方 slowdown 有多大；
3. 相对 base bank phase 是否显著影响拥塞和总完成时间。

### 8.2 场景

| 场景 | SMU | core workload | 目的 |
| --- | --- | --- | --- |
| C0 | standalone | standalone separately | 建立 `T_smu`、`T_core` |
| C1 | merge | register-only integer/FPU | 测无 TCDM 干扰 overlap |
| C2 | merge | RVV vector copy/add | 测 TCDM 带宽竞争 |
| C3 | merge | RVV streaming + phase sweep | 测 bank phase 敏感度 |

C1 的 core workload 应通过迭代数校准到与 SMU standalone 时间接近，避免 workload
过短导致 overlap 指标只反映启动开销。C1 测量循环内不得含 load/store。

C2 使用固定、可复现的 RVV copy 或 add kernel，并报告 bytes/cycle、访问数组大小和
是否发生 tail。

### 8.3 bank phase 扫描

由于两个 streaming workload 都会跨越 bank，不能宣称将它们放在完全分离的
bank。固定 SMU base 后，对 core buffer 使用：

```text
relative base offset = {0,8,16,...,120} bytes
```

共 16 个 bank phases。每个 phase 使用相同数据量和地址间距，只改变
`addr[6:3]` 相位。报告：

- 最好、最差和中位 phase；
- phase 对 `tcdm_congested` 的影响；
- phase 对 SMU/core slowdown 和总时间的影响。

### 8.4 同步与测量窗口

测量区域内禁止持续 MMIO polling，因为 polling 本身会制造互连/TCDM 干扰。
推荐顺序：

1. 配置并启动 SMU；
2. core 立即执行目标 workload；
3. workload 完成后再检查 SMU；
4. 必要时等待 SMU done；
5. 从 VCD/done transition 提取 SMU 完成时间，或增加低扰动 busy-cycle counter。

若使用计数器，必须说明计数器读取是否位于测量窗口外。

### 8.5 指标

首先检查并发是否有收益：

```text
T_concurrent < T_smu + T_core
```

定义 overlap efficiency：

```text
eta_overlap =
  (T_smu + T_core - T_concurrent) / min(T_smu, T_core)
```

定义双方 slowdown：

```text
slowdown_smu  = T_smu_concurrent  / T_smu_alone
slowdown_core = T_core_concurrent / T_core_alone
```

解释边界：

- 无干扰且完全 overlap 时，`eta_overlap` 接近 1；
- 完全串行时，`eta_overlap` 接近 0；
- 因测量噪声或竞争可能出现小于 0 或大于 1 的原始值；
- 保留原始值和误差，不为图表美观强制 clamp。

同时记录：

```text
tcdm_accessed
tcdm_congested
congestion_ratio
core bytes/cycle
SMU elements/cycle
bank phase
```

### 8.6 验收

1. C0/C1/C2 均完成至少 3 次重复；
2. C3 覆盖 16 个 phase；
3. 并发窗口内没有高频 MMIO polling；
4. 同时给出 `T_smu`、`T_core`、`T_concurrent`，而不只给 speedup；
5. 能区分“释放 core 执行资源”与“共享 TCDM 导致竞争”两种效应；
6. 失败/负 overlap 结果必须保留并解释。

## 9. 执行优先级、依赖和停止条件

### 9.1 P0：当前论文证据链的核心必做项

按顺序执行：

1. 重构 benchmark buffer、统一计时/正确性/CSV 框架；
2. 补齐 B1、B2-R、B3 公平 baseline；
3. 跑 anchor、tail correctness 和强制规模矩阵；
4. 计算 break-even，拟合规模模型；
5. 完成 Full SMU FSM 周期分解；
6. 完成 core–SMU C0/C1/C2/C3 与 bank-phase sweep；
7. 工程化 Yosys Slang generic resource proxy；
8. 对代表点生成并解析 RTL VCD toggle proxy。

### 9.2 P1：需要额外代码支持的增强项

1. B0/B2-F target `expf` baseline；
2. A1 scalar-only mode；
3. VCD trace gating 或低扰动 busy-cycle counter；
4. TCDM 容量边界探测；
5. 更多 seed、更多规模或更细的数值边界覆盖。

### 9.3 P2：外部环境条件项

1. ASIC cell area、Fmax 和 timing closure；
2. post-P&R cluster area overhead；
3. gate-level/post-layout SAIF power；
4. total/incremental physical energy。

若缺少外部工具或工艺文件，应记录：

```text
status = blocked_external
missing = <tool/library/PDK/constraint>
required_next_action = <具体条件>
```

这属于正确的实验结论，不应使用 generic cells 或 toggles 冒充物理结果。

### 9.4 逐阶段 go/no-go

- **框架 gate**：anchor 未全部正确前，不启动全规模矩阵；
- **RVV gate**：反汇编未确认 RVV 指令前，不接受 B2 结果；
- **数值 gate**：主域 correctness 未通过前，不发布性能 speedup；
- **容量 gate**：footprint 超过 70% TCDM 的点不进入主矩阵；
- **VCD gate**：窗口起止无法稳定识别时，不统计 toggle；
- **PPA gate**：没有 library/PDK/约束时，不产生物理单位；
- **并发 gate**：存在测量区 polling 时，不接受 overlap 结论。
