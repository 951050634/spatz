# 一些思考

本文档记录2026-06-09与Claude Code对话中产生的关键思考和洞见。

## 1. 性能数据本质的澄清

### Cycle vs Runtime

**核心认知**：SMU项目的所有性能评估都是基于cycle的，没有提供真实的wall-clock time测量。

**原因分析**：
- Cycle是更精确的指标，消除了OS调度、I/O等待等噪声
- 硬件架构论文通常使用cycle作为主要性能指标
- 在固定频率假设下，cycle比例可以作为runtime比例的proxy

**文档表述的严谨性**：
> "这张图适合组会展示'运行时间趋势'，但严格来说它仍然来源于 cycle，而不是 wall time。"

### 为什么文档要强调"runtime proxy"？

这主要是学术表述的严谨性考虑：
1. **明确假设** - 说明这是基于相同频率的估计
2. **区分概念** - cycle ≠ wall-clock time
3. **学术规范** - 避免过度声称"实际运行时间加速"

但在受控的Verilator仿真环境中，cycle比例**确实可以直接转换为**相同频率下的runtime比例。

## 2. 第二周性能跃升的根本原因

### 从2.40x到37.89x的质变

**第一周（受限语义）**：
- 支持的情况：`l_old=0`或`l_tile=0`，或`m_old==m_tile && l_old==l_tile`
- 不需要计算exp()或除法
- CPU和SMU的计算都很简单

**第二周（完整mixed-scalar）**：
- 实现完整online softmax方程：
  ```text
  m_new = max(m_old, m_tile)
  l_new = l_old * exp(m_old - m_new) + l_tile * exp(m_tile - m_new)
  O_new = O_old * (l_old * exp(m_old - m_new) / l_new) + ...
  ```
- 需要计算exp()和除法

### 加速比差异的三个原因

1. **CPU参考路径的计算复杂度爆炸**
   - 第一周：CPU cycles = 23,013 (N=16,D=64)
   - 第二周：CPU cycles = 365,620 (N=16,D=64)
   - **CPU计算量增加了约16倍**

2. **SMU硬件加速的优势充分发挥**
   - SMU的LUT近似单元并行计算exp和reciprocal
   - 硬件乘法器加速Q1.23/Q16.32定点运算
   - **硬件加速效果在复杂计算中显现**

3. **数据规模效应的体现**
   - N=16, D=64 → 1024个元素
   - 每个元素都需要2次exp、1次reciprocal、多次定点乘法
   - 这些操作的硬件加速收益累积起来

### 关键数据对比

| 指标 | 第一周 | 第二周 | 变化 |
|------|--------|--------|------|
| CPU cycles | 23,013 | 365,620 | **+15.9x** |
| Engine cycles | 9,607 | 9,650 | 基本不变 |
| Speedup | 2.40x | 37.89x | **+15.8x** |

**结论**：加速比的提升主要来自**CPU计算复杂度的增加**，而SMU的cycle数基本保持不变。

## 3. 频率一致性的证明

### CPU频率没有变化的铁证

1. **硬件连接层面**
   ```systemverilog
   // SMU和CPU都连接同一个clk_i
   .clk_i (clk_i),  // online_merge_update_engine
   .clk_i (clk_i),  // spatz_cc (CPU core)
   ```

2. **软件测量层面**
   ```c
   size_t benchmark_get_cycle() { return read_csr(mcycle); }
   ```
   - 所有cycle都来自`mcycle` CSR
   - CPU和SMU使用同一计数器

3. **排除的干扰因素**
   - 没有时钟门控导致的频率变化
   - 没有动态电压频率调整(DVFS)
   - 没有不同的时钟域
   - 没有仿真器配置的变化

### 给组会的明确表述

> "我们的cycle测量是基于RISC-V的`mcycle` CSR，SMU和CPU core共享同一个系统时钟`clk_i`。因此cycle比例直接等于runtime比例。"

## 5. 论文定位的关键思考

### A+B合成一篇文章的策略

**文章定位**：Architecture/System Prototype Paper

**核心叙事**：
> "本文研究如何在不修改 Spatz ISA 和主指令流水线的前提下，为 online softmax merge 提供一个低侵入硬件 offload 路径。第一阶段通过受限语义验证 MERGE engine 的系统集成可行性；第二阶段进一步实现完整 mixed-scalar online softmax merge 公式，并通过 RTL correctness、近似误差和 microbenchmark 性能数据证明该路径具备扩展到 attention workload 的潜力。"

**更精炼的thesis**：
> "Online softmax merge is small enough to be offloaded through an auxiliary merge engine, but structured enough to require full mixed-scalar datapath support. We show that an interface-preserving SMU design can implement the complete merge recurrence with LUT-based approximations, pass RTL correctness gates, and reduce merge-cycle cost by up to 37.9x on evaluated microbenchmarks."

### 可以主张的贡献

1. 非侵入式cluster-local offload engine
2. 完整mixed-scalar merge datapath的RTL实现
3. 可控近似误差（< 1e-5）
4. Microbenchmark性能数据（最高37.89x）

### 不能主张的贡献

1. 端到端attention/LLM加速
2. 实际wall-clock time加速（需要固定频率假设）
3. DRAM/Runtime调度的优化

## 8. Spatz 平台整体硬件架构设计

### 8.1 三层架构体系

Spatz 平台采用经典的三层架构设计：

```
┌─────────────────────────────────────────────────────────────┐
│                    系统层 (hw/system/)                       │
│  ┌─────────────────────────────────────────────────────┐    │
│  │              spatz_cluster                          │    │
│  │  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐ │    │
│  │  │ Core CC #0  │  │ Core CC #1  │  │ Core CC #N  │ │    │
│  │  │ (Snitch+    │  │ (Snitch+    │  │ (Snitch+    │ │    │
│  │  │  Spatz)     │  │  Spatz)     │  │  Spatz)     │ │    │
│  │  └─────────────┘  └─────────────┘  └─────────────┘ │    │
│  │              Shared TCDM (L1 Scratchpad)            │    │
│  │              AXI External Memory Interface          │    │
│  └─────────────────────────────────────────────────────┘    │
└─────────────────────────────────────────────────────────────┘
                              │
┌─────────────────────────────┴───────────────────────────────┐
│                    IP 层 (hw/ip/)                            │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────────────┐   │
│  │   spatz     │ │  spatz_cc   │ │  online_merge       │   │
│  │ (向量核心)   │ │ (核心复合体) │ │ (专用加速器)         │   │
│  └─────────────┘ └─────────────┘ └─────────────────────┘   │
│  ┌─────────────┐ ┌─────────────┐ ┌─────────────┐           │
│  │   snitch    │ │  mem_intf   │ │  tcdm_intf  │           │
│  │ (标量核心)   │ │ (内存接口)   │ │ (TCDM接口)   │           │
│  └─────────────┘ └─────────────┘ └─────────────┘           │
└─────────────────────────────────────────────────────────────┘
                              │
┌─────────────────────────────┴───────────────────────────────┐
│                  工具层 (util/)                              │
│         集群生成器、配置管理、RTL 生成工具                    │
└─────────────────────────────────────────────────────────────┘
```

### 8.2 核心设计原则

#### 8.2.1 紧耦合异构计算
- **标量+向量紧耦合**：Snitch 标量核心 + Spatz 向量协处理器共享同一时钟域
- **指令级协同**：通过 X-Interface 实现标量指令与向量指令的协同执行
- **共享内存模型**：通过 TCDM 实现低延迟的数据共享

#### 8.2.2 层次化内存架构
```
外部 DRAM (2GB @ 0x80000000)
         │ AXI 接口
         ▼
    Shared TCDM (128KB @ 0x00100000)  ← L1 暂存器
         │
    ┌────┴────┐
    │  Core   │  每个核心复合体包含：
    │ Complex │  - Snitch 标量核心
    │         │  - Spatz 向量单元
    │         │  - DMA 控制器
    └─────────┘
```

**关键约束**：
- VLSU 只能访问本地 TCDM，不能直接访问外部 DRAM
- 数据移动必须通过 `snrt_l1alloc()` + DMA 完成
- TCDM 提供单周期访问延迟

#### 8.2.3 可配置的并行度
通过 HJSON 配置文件控制：
```hjson
{
  "n_fpu": 4,           // 每个 VFU 中的 FPU 数量
  "n_ipu": 1,           // 每个 VFU 中的 IPU 数量  
  "vlen": 256,          // 向量长度
  "spatz_nports": 2,    // VLSU 端口数
  "cores": [...]        // 核心数量和配置
}
```

### 8.3 Spatz 向量处理器内部架构

#### 8.3.1 功能单元划分
```
                    ┌─────────────────┐
                    │   Controller    │ ← 指令解码、调度、写回
                    └────────┬────────┘
                             │
        ┌────────────────────┼────────────────────┐
        ▼                    ▼                    ▼
   ┌─────────┐         ┌─────────┐         ┌─────────┐
   │   VFU   │         │  VLSU   │         │  VSLDU  │
   │(算术单元)│         │(访存单元)│         │(滑动单元)│
   └────┬────┘         └────┬────┘         └────┬────┘
        │                   │                   │
        └───────────────────┼───────────────────┘
                            ▼
                    ┌───────────────┐
                    │      VRF      │ ← 向量寄存器文件
                    │  (多端口设计)  │
                    └───────────────┘
```

#### 8.3.2 VRF 多端口设计
```systemverilog
// 写端口：1(VFU) + 1(SLDU) + NumVLSUInterfaces(VLSU)
localparam int unsigned NrWritePorts = 2 + NumVLSUInterfaces;

// 读端口：3(VFU) + 1(SLDU) + 2*NumVLSUInterfaces(VLSU)  
localparam int unsigned NrReadPorts = 4 + 2*NumVLSUInterfaces;
```

**设计动机**：
- 支持 VFU、VLSU、VSLDU 的并发访问
- 通过银行化（4 banks）减少端口冲突
- 采用写缓冲机制（`BUF_FPU`）隐藏写冲突

#### 8.3.3 冲突处理机制
```systemverilog
`ifdef BUF_FPU
  // FPU 写缓冲：解决 VRF 端口竞争
  fifo_v3 #(.DEPTH(FpuBufDepth)) i_vfu_buf (...);
  
  // 缓冲策略：当 VRF 端口不可用时，临时存储 FPU 结果
  assign vfu_buf_en = sb_we[VFU_VD_WD] && 
                     (!vrf_wvalid[VFU_VD_WD] || 
                      (vrf_wvalid[VFU_VD_WD] && !vfu_buf_empty));
`endif
```

### 8.4 内存接口与数据流

#### 8.4.1 TCDM 接口抽象
```systemverilog
// TCDM 请求/响应接口
interface tcdm_req_t;
  logic                    q_valid;
  logic [AddrWidth-1:0]    q.addr;
  logic                    q.write;
  logic [DataWidth-1:0]    q.data;
  logic [StrbWidth-1:0]    q.strb;

```

#### 8.4.2 典型数据流
```
1. 数据初始位置：DRAM
2. DMA 传输：DRAM → TCDM (通过 snrt_dma_start_1d)
```

## 9. Online Softmax Merge-Update Engine 专用加速器设计

### 9.1 设计定位与动机

#### 9.1.1 目标工作负载特征
```
┌─────────────────────────────────────────────────────────────┐
│              Online Softmax Merge Workload                  │
├─────────────────────────────────────────────────────────────┤
│  算力需求    │ 低算强 (compute-light)                        │
│  访存模式    │ 强状态依赖 (state-heavy)                      │
│  计算模式    │ 在线归一化 (online normalization)             │
│  状态生命周期│ 短生命周期更新 (short-lived state updates)    │
│  数据规模    │ 中等规模矩阵 (N×D, 典型 16-128)               │
└─────────────────────────────────────────────────────────────┘
```

#### 9.1.2 设计目标
1. **最小侵入性**：不修改 Spatz ISA、decoder、controller、VFU、VRF
2. **cluster 级共享**：一个引擎服务整个 cluster
3. **TCDM 本地优化**：仅访问 TCDM，不直接访问 DRAM
4. **FP32 语义优先**：首先保证数值正确性

### 9.2 硬件架构概览

#### 9.2.1 系统集成位置
```
┌─────────────────────────────────────────────────────────────┐
│                    Spatz Cluster                            │
│  ┌─────────────┐    ┌─────────────────────────────┐        │
│  │   Spatz     │    │    Merge Engine (SMU)       │        │
│  │ Core CCs    │    │  ┌─────────────────────┐   │        │
│  │             │    │  │ Update Engine FSM   │   │        │
│  │  ┌───────┐  │    │  │ ┌─────┐ ┌─────┐     │   │        │
│  │  │ VFU   │  │    │  │ │Exp  │ │Recip│     │   │        │
│  │  │ VRF   │  │    │  │ │LUT  │ │LUT  │     │   │        │
│  │  │ VLSU  │  │    │  │ └─────┘ └─────┘     │   │        │
│  │  └───────┘  │    │  │   定点运算单元       │   │        │
│  └─────────────┘    │  └─────────────────────┘   │        │
│         │           │            │               │        │
│         └───────────┼────────────┘               │        │
│                     │ TCDM Master Port           │        │
│              ┌──────┴──────┐                     │        │
│              │  Shared     │                     │        │
│              │   TCDM      │ ◄───────────────────┘        │
│              └─────────────┘                              │
└─────────────────────────────────────────────────────────────┘
```

#### 9.2.2 核心设计决策
| 设计维度 | 选择 | 理由 |
|---------|------|------|
| 控制方式 | MMIO 寄存器 | 软件配置灵活，硬件实现简单 |
| 访问模式 | TCDM Master | 避免 DRAM 延迟，单周期访问 |
| 数据格式 | FP32 | 首先保证语义正确性 |
| 计算精度 | Q1.23/Q16.32 定点 | 硬件实现高效，误差可控 |
| 近似方法 | 256段 LUT | 平衡精度和硬件开销 |

### 9.3 核心硬件模块详解

#### 9.3.1 顶层状态机
```systemverilog
typedef enum logic [2:0] {
  IDLE,           // 等待启动
  LOAD_SCALAR,    // 批量加载 m/l 标量 (4个元素)
  COMPUTE_SCALAR, // 计算 m_new, l_new
  COMPUTE_WEIGHT, // 计算归一化权重
  STORE_SCALAR,   // 写回 m_new, l_new  
  UPDATE_VECTOR,  // 逐元素更新 O 向量
  DONE,           // 完成
  ERROR           // 错误状态
} state_e;
```

**状态转换逻辑**：
```
IDLE → LOAD_SCALAR (start_i 有效且配置合法)
LOAD_SCALAR → COMPUTE_SCALAR (4个标量加载完成)
COMPUTE_SCALAR → COMPUTE_WEIGHT (exp 近似完成)
COMPUTE_WEIGHT → STORE_SCALAR (reciprocal 近似完成)
STORE_SCALAR → UPDATE_VECTOR (标量写回完成)
UPDATE_VECTOR → LOAD_SCALAR/ DONE (行处理完成/全部完成)
```

#### 9.3.2 近似计算单元

**指数近似器 (`online_merge_exp_approx`)**：
```systemverilog
// 输入：FP32，范围 [-8.0, 0.0]
// 输出：Q1.23 定点 × 2^0
// LUT：256 段，线性插值
module online_merge_exp_approx (
  input  fp32_bits_t x_i,
  output q1_23_t     exp_q1_23_o,
  output logic       valid_o,
  output logic       saturated_o,    // x > 0 时饱和到 1.0
  output logic       unsupported_o   // x < -8 时不支持
);
```

**倒数近似器 (`online_merge_recip_approx`)**：
```systemverilog
// 输入：正的有限正规 FP32
// 输出：recip × 2^scale_exp (分离指数)
// LUT：256 段
module online_merge_recip_approx (
  input  fp32_bits_t x_i,
  output q1_23_t     recip_q1_23_o,
  output logic signed [9:0] scale_exp_o,
  output logic       valid_o,
  output logic       unsupported_o
);
```

#### 9.3.3 定点运算数据通路

**数据类型层次**：
```
FP32 (IEEE 754) 
  ↓ fp32_abs_to_uq16_16
Q16.32 (uq16_16_t) - 无符号定点
  ↓ 算术运算
Q1.23 (q1_23_t) - 用于 exp/reciprocal 近似
  ↓ q1_23_mul_uq16_16  
Q16.32 - 加权累加结果
  ↓ uq16_16_to_fp32
FP32 - 写回内存
```

**关键运算单元**：
```systemverilog
// Q1.23 × Q16.32 → Q16.32
function automatic uq16_16_t q1_23_mul_uq16_16(
  input uq16_16_t lhs, input q1_23_t rhs
);

// 带符号加权乘法
function automatic sq16_16_t sq16_16_mul_weight(
  input sq16_16_t value, input uq16_16_t weight
);

// 带指数缩放的乘法
function automatic uq16_16_t q1_23_scaled_mul_uq16_16(
  input uq16_16_t lhs, input q1_23_t rhs, 
  input logic signed [9:0] scale_exp
);
```

### 9.4 内存访问优化

#### 9.4.1 访问模式分类

**标量访问（m/l 状态）**：
```systemverilog
// 行主序，4字节对齐
scalar_addr = base + (row << 2);

// 一次加载4个标量：m_old, l_old, m_tile, l_tile
// 减少 TCDM 访问次数
```

**向量访问（O 矩阵）**：
```systemverilog
// 支持两种布局：
// 1. Packed layout (stride=0)：O[row][elem] = base + row*D*4 + elem*4
// 2. Strided layout (stride>0)：O[row][elem] = base + row*stride + elem*4

eff_stride = (stride == 0) ? (d << 2) : stride;
vector_addr = base + row * eff_stride + (elem << 2);
```

#### 9.4.2 TCDM 接口协议
```systemverilog
// 请求通道
tcdm_req_o.q_valid = req_valid_q;
tcdm_req_o.q.addr = req_addr_q;  
tcdm_req_o.q.write = req_write_q;
tcdm_req_o.q.data = req_wdata_q;
tcdm_req_o.q.strb = req_strb_q;

// 响应通道  
if (read_pending_q && tcdm_rsp_i.p_valid) begin
  // 处理读响应
end
```

### 9.5 错误处理与边界条件

#### 9.5.1 配置合法性检查
```systemverilog
function automatic logic valid_cfg;
  // 1. 维度检查
  valid_cfg = (n_i != 0) && (d_i != 0);
  
  // 2. 步长对齐检查  
  stride_aligned = (stride_i == 0) || (stride_i[1:0] == 2'b00);
  
  // 3. 地址对齐检查
  all_aligned = is_aligned(src_m_old_i) && is_aligned(src_l_old_i) && ...
                && is_aligned(dst_m_i) && is_aligned(dst_l_i) && ...;
endfunction
```

#### 9.5.2 数值有效性检查
```systemverilog
function automatic logic supported_scalar_merge(...);
  supported_scalar_merge =
    // m 必须是有限正规数或零
    fp32_is_finite_normal_or_zero(m_old_bits) &&
    fp32_is_finite_normal_or_zero(m_tile_bits) &&
    
    // l 必须是非负的有限正规数或零
    fp32_is_nonnegative_finite_normal_or_zero(l_old_bits) &&
    fp32_is_nonnegative_finite_normal_or_zero(l_tile_bits) &&
    
    // 排除 both-zero-l 情况（数学上无定义）
    !((l_old_bits == 0) && (l_tile_bits == 0));
endfunction
```

#### 9.5.3 错误状态分类
| 错误类型 | 触发条件 | 处理方式 |
|---------|----------|----------|
| 配置错误 | 地址未对齐、维度为0 | ERROR 状态，error_o=1 |
| 数值错误 | NaN/Inf/subnormal | ERROR 状态，error_o=1 |
| Both-zero-l | l_old=l_tile=0 | ERROR 状态，error_o=1 |
| 近似不支持 | exp 输入 < -8 | ERROR 状态，error_o=1 |

### 9.6 性能优化策略

#### 9.6.1 计算优化
1. **LUT 并行**：exp 和 reciprocal 近似器并行工作
2. **定点加速**：核心运算使用 Q16.32 定点，避免 FP32 复杂运算
3. **批量处理**：一次加载4个标量，减少状态机切换开销

#### 9.6.2 访存优化  
1. **就地更新**：直接在 TCDM 中更新，避免数据搬运
2. **顺序访问**：行主序访问模式，利于缓存
3. **双字访问**：利用 64-bit TCDM 接口，一次传输2个 FP32

#### 9.6.3 流水线优化
```
标量阶段：LOAD → COMPUTE → STORE (3个周期/行)
向量阶段：READ_O_OLD → READ_O_TILE → COMPUTE → WRITE_O (4个周期/元素)
```

### 9.7 软件接口设计

#### 9.7.1 MMIO 寄存器映射
```c
// 源地址配置
#define MERGE_SRC_M_OLD    0x000  // m_old 矩阵基地址
#define MERGE_SRC_L_OLD    0x004  // l_old 向量基地址  
#define MERGE_SRC_O_OLD    0x008  // O_old 矩阵基地址
#define MERGE_SRC_M_TILE   0x00C  // m_tile 矩阵基地址
#define MERGE_SRC_L_TILE   0x010  // l_tile 向量基地址
#define MERGE_SRC_O_TILE   0x014  // O_tile 矩阵基地址

// 目标地址配置  
#define MERGE_DST_M        0x018  // m_new 输出基地址
#define MERGE_DST_L        0x01C  // l_new 输出基地址
#define MERGE_DST_O        0x020  // O_new 输出基地址

// 维度配置
#define MERGE_N            0x024  // 行数 N
#define MERGE_D            0x028  // 列数 D  
#define MERGE_STRIDE       0x02C  // O 矩阵行步长 (0=packed)

// 控制和状态
#define MERGE_CTRL         0x030  // 控制寄存器
#define   MERGE_CTRL_START      (1<<0)
#define   MERGE_CTRL_CLEAR_DONE (1<<1)
#define MERGE_STATUS       0x034  // 状态寄存器
#define   MERGE_STATUS_BUSY     (1<<0)  
#define   MERGE_STATUS_DONE     (1<<1)
#define   MERGE_STATUS_ERROR    (1<<2)
```

#### 9.7.2 典型使用流程
```c
// 1. 配置地址和参数
write_csr(MERGE_SRC_M_OLD, (uint32_t)&m_old);
write_csr(MERGE_SRC_L_OLD, (uint32_t)&l_old);
// ... 配置其他地址

write_csr(MERGE_N, N);
write_csr(MERGE_D, D);
write_csr(MERGE_STRIDE, stride);

// 2. 启动引擎
write_csr(MERGE_CTRL, MERGE_CTRL_START);

// 3. 等待完成
while (read_csr(MERGE_STATUS) & MERGE_STATUS_BUSY);

// 4. 检查错误
if (read_csr(MERGE_STATUS) & MERGE_STATUS_ERROR) {
  // 处理错误
}

// 5. 清除完成标志
write_csr(MERGE_CTRL, MERGE_CTRL_CLEAR_DONE);
```

### 9.8 设计权衡与局限

#### 9.8.1 已接受的限制
1. **不支持 subnormal**：FP32 subnormal 数视为 unsupported
2. **LUT 近似误差**：最大误差 < 1e-5，可接受的精度损失
3. **TCDM 容量限制**：仅支持 TCDM 内数据，不支持 DRAM spilling
4. **单引擎设计**：cluster 级共享，可能成为热点

#### 9.8.2 可扩展方向
1. **多引擎并行**：为每个核心配备独立引擎
2. **DRAM 支持**：添加 AXI master 接口支持外部内存
3. **更高精度**：增加 LUT 段数或支持 FP64
4. **ISA 扩展**：添加专用指令实现更紧密集成
