# 逐级 Baseline、消融实验与规模矩阵结论

本文档总结当前 online softmax merge 补充实验中已经正式闭环的结果，并说明
哪些结论仍受实验范围限制。主要证据来自：

- `docs/online-softmax-merge-engine/SUPPLEMENT_PROGRESS.md`；
- `work-artifacts/work-online-merge-stage4-scaling-formal-20260715T151558Z/analysis.json`；
- `work-artifacts/work-online-merge-stage5b-fsm-analysis-20260715T183542Z/analysis.json`。

## 1. 逐级 Baseline 实验结论

### 1.1 Baseline 定义

当前逐级比较中的主要实现为：

| 编号 | 实现 | 作用 |
| --- | --- | --- |
| B1 | RTL-aligned scalar software | 同硬件数值语义的标量软件参考 |
| B2-R | RTL-aligned scalar weights + RVV vector update | 同语义、高性能软件 baseline |
| B3 | Full SMU | 完整硬件卸载方案 |

其中，B2-R 是判断硬件是否真正优于优化软件实现的关键 baseline。历史上相对旧
scalar reference 得到的约 `37.89x` 加速不能替代 B3 对 B2-R 的正式比较。
B0/B2-F（自然 `expf` 语义的软件路径）尚未形成与主矩阵同等级的正式闭环，因此
当前不应把它们写入 headline 结论。

### 1.2 核心结论

1. **B3 在所有直接测量的 break-even 点上均快于 B2-R。**
   在 `N={1,2,4,8}`、`D={1,8,16,32}` 的 16 个直接测量点中，均满足
   `C_B3 <= C_B2-R`。实测加速比范围为：

   - 最低：`1.424x`，位于 `(N,D)=(1,32)`；
   - 最高：`10.140x`，位于 `(N,D)=(8,1)`。

2. **在当前测量范围内，硬件的 break-even 已经出现在最小测试维度 `D=1`。**
   对 `N=1、2、4、8`，最小实测获益维度都是 `D=1`。该结论只适用于已测点，
   不能外推为所有未测规模都必然获益。

3. **SMU 的主要优势来自消除软件端高昂的逐行标量开销。**
   正式拟合模型为：

   ```text
   C(N,D) = C0 + Cs*N + Cv*N*D + Cstall
   ```

   | 实现 | 固定开销 `C0` | 每行开销 `Cs` | 每元素开销 `Cv` | `R²` |
   | --- | ---: | ---: | ---: | ---: |
   | B2-R | 483.353 | 1538.127 | 2.056 | 0.999738 |
   | B3 | 1058.654 | 22.029 | 7.995 | 0.999967 |

   B3 的固定启动成本和每元素成本高于 B2-R，但每行标量成本从约
   `1538 cycles/row` 降至约 `22 cycles/row`。因此，当行数 `N` 增加时，硬件能
   迅速摊薄启动开销并取得明显收益。

4. **加速比不保证随 `D` 单调增加。**
   RVV 的向量更新每元素成本较低，而当前 SMU 的 vector streaming 每元素拟合
   成本较高。因此，固定 `N` 时增大 `D` 会提高向量部分权重，可能压低相对
   B2-R 的加速比。例如，`N=8` 时从 `D=1` 的约 `10.14x` 降至 `D=32` 的约
   `4.15x`。这不是硬件失效，而是瓶颈由 scalar merge 转向 vector update。

5. **TCDM 拥塞不是当前性能趋势的主导因素。**
   B2-R 拟合点的 median congestion 均为 0；B3 的最大实测拥塞比例约为
   `0.777%`（`N=32,D=64`）。残差符号也未随拥塞单调变化，因此当前证据支持
   “紧凑模型能很好描述周期”，但不支持把残差直接解释为拥塞造成的 stall。

## 2. 消融实验结论

### 2.1 当前已完成和未完成的消融

| 编号 | scalar merge | `O[D]` update | 状态 |
| --- | --- | --- | --- |
| A0 | B2-R software | RVV | 已完成 |
| A1 | SMU | RVV | 尚未完成，需要 scalar-only mode 与权重回读 |
| A2 | SMU | SMU | 已完成 |

因此，当前正式结论来自：

- A0 与 A2 的端到端比较；
- A2 内部 FSM 的 scalar/vector 周期分解。

目前不能声称已经独立测得“A1 对 A0 的收益”以及“A2 对 A1 的额外收益”，也不能
用估算柱代替 A1 实测。

### 2.2 A0 与 A2 的端到端结果

| 规模 `(N,D)` | A0 cycles | A2 cycles | A2 speedup | A2 TCDM congestion |
| --- | ---: | ---: | ---: | ---: |
| `(1,1)` | 1966 | 1124 | 1.749x | 0 / 321 |
| `(8,32)` | 13547 | 3263 | 4.152x | 11 / 1524，约 0.72% |
| `(16,64)` | 27532 | 9556 | 2.881x | 38 / 5036，约 0.75% |

结论如下：

1. Full SMU 在三个 anchor 点上都优于同语义 RVV 软件路径；
2. 收益并非随问题规模简单单调增加：从 `(8,32)` 到 `(16,64)`，vector update
   占比继续上升，使加速比由 `4.152x` 降至 `2.881x`；
3. A2 的 TCDM 访问数高于 A0，但拥塞比例仍低于 1%，不足以解释主要周期变化。

### 2.3 FSM 阶段分解

| 规模 `(N,D)` | scalar cycles | vector cycles | busy cycles | scalar/busy | vector/busy | 非 busy 端到端开销 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `(1,1)` | 20 | 9 | 29 | 68.97% | 31.03% | 1095 cycles，97.42% |
| `(8,32)` | 160 | 2063 | 2223 | 7.20% | 92.80% | 1040 cycles，31.87% |
| `(16,64)` | 320 | 8214 | 8534 | 3.75% | 96.25% | 1022 cycles，10.69% |

由此可得到三个重要结论：

1. **scalar 硬件路径已经不是中大规模的主要瓶颈。**
   scalar 部分约为 `20 cycles/row`，其 busy 占比从 `(1,1)` 的 68.97% 降至
   `(16,64)` 的 3.75%。这与 baseline 拟合中 B3 极低的每行成本相吻合。

2. **中大规模的主要瓶颈已经转移到 vector streaming。**
   `(8,32)` 和 `(16,64)` 中，`UPDATE_VECTOR` 分别占 busy cycles 的 92.80% 和
   96.25%。后续若继续优化性能，优先方向应是提高 vector update 吞吐、减少
   每元素周期，而不是继续压缩 scalar nonlinear path。

3. **极小规模主要受固定的软件/命令开销支配。**
   `(1,1)` 的 SMU 真正 busy 只有 29 cycles，但端到端为 1124 cycles，约
   97.42% 是 command/setup/wait 等非 busy 开销。这说明小规模优化重点应是批量
   提交、降低启动/同步成本，或通过并发隐藏固定开销。

### 2.4 当前消融结论的边界

由于 A1 尚未实现，目前只能证明“完整 SMU 优于完整 RVV 软件路径”，并能定位
SMU 内部的阶段占比；还不能严格量化：

- 仅将 scalar merge 卸载到 SMU 能获得多少收益；
- vector update 从 RVV 转移到 SMU 后究竟增加或减少多少周期；
- 权重写回、读回以及同步成本对 A1 的影响。

## 3. 不同规模矩阵结果是否可以可视化

**可以，而且非常适合可视化。** 当前数据已经是结构化的 JSON/CSV，不需要重新
运行仿真即可生成论文图。建议至少绘制以下五类图。

### 3.1 周期热力图

- 横轴：`D`；纵轴：`N`；
- 分别绘制 B2-R 和 B3 median cycles；
- 使用对数色标，避免大小规模间数量级差异掩盖细节。

该图回答“不同矩阵规模下，软件和硬件的绝对代价如何变化”。

### 3.2 加速比热力图

- 每个格点绘制 `B2-R cycles / B3 cycles`；
- 以 `1.0x` 为盈亏分界；
- 可在格内直接标注 speedup 数值。

这是最适合呈现适用范围和 break-even 的主图。当前 16 个 break-even 点全部高于
`1.0x`。

### 3.3 固定 N 的规模折线图

- 横轴使用 `D`；
- 纵轴可分别使用 cycles、cycles/element 或 speedup；
- 每条曲线对应一个 `N`。

这类图能清楚展示：随着 `D` 增大，vector 部分权重上升，B3 相对 B2-R 的加速
可能下降，而不是简单随矩阵规模增大而上升。

### 3.4 FSM 堆叠柱状图

对 `(1,1)`、`(8,32)`、`(16,64)` 绘制：

- scalar cycles；
- vector cycles；
- command/setup/wait 等非 busy cycles。

建议同时提供两张：一张画绝对 cycles，一张归一化为 100%。这样可以同时看到
绝对开销与瓶颈迁移。

### 3.5 拟合曲面与残差图

- 分别绘制 B2-R/B3 的 `C0 + Cs*N + Cv*N*D` 拟合曲面；
- 用散点标出实测值；
- 单独绘制残差随 `N、D` 或 congestion ratio 的变化。

该图可用于说明紧凑模型拟合度很高，但残差不能直接解释为 TCDM stall。

## 4. 推荐用于论文的图表组合

若版面有限，优先使用：

1. **主图：speedup heatmap**，展示不同 `N,D` 下的适用范围；
2. **消融图：FSM 归一化堆叠柱状图**，展示 scalar 到 vector 的瓶颈迁移；
3. **补充图：B2-R/B3 cycles 折线图**，展示绝对周期及非单调 speedup；
4. **补充表：16 点 break-even 表**，保留可复核的准确数字。

绘图时必须区分“直接测量点”和“模型预测点”。不能将拟合预测混入实测热力图，
也不能对未测的 `D` 宣称已经验证 break-even。

## 5. 一句话总结

逐级 baseline 表明，Full SMU 的主要价值是把软件中高昂的逐行 scalar merge
开销降至很低，因此在全部 16 个直接测量的 break-even 点上均优于同语义 RVV
baseline；消融结果进一步表明，中大规模时瓶颈已转移到 SMU 的 vector update，
而极小规模主要受固定启动和同步开销支配。不同规模矩阵的结果不仅可以可视化，
而且应以 speedup 热力图、周期折线图和 FSM 堆叠柱状图联合呈现。
