\title{Selective Recurrence Offloading for Online Softmax Merge on RISC-V Vector Clusters}
\author{Anonymous Author(s)}

\begin{abstract}
Blockwise attention repeatedly combines tile results through Online Softmax
Merge. Each merge contains two different forms of computation: a
state-dependent scalar recurrence over the maximum and normalization state,
and a regular $O[D]$ vector update. The recurrence forms a short dependency
chain with maximum, exponential, accumulation, and reciprocal operations. The
vector phase applies two ready weights independently across $D$ elements. We
identify this recurrence--vector computational asymmetry and propose selective
recurrence offloading: a Scalar Softmax Merge Unit (SMU) specializes the
recurrence, while an existing vector datapath retains the element-wise update.
A shared scratchpad transfers the updated state and weights between phases. We
instantiate this architecture on the open-source Spatz RISC-V vector cluster
without modifying its instruction set or RVV datapath. Across three
model-derived merge shapes, the prototype achieves a 4.53$\times$
geometric-mean RTL/Verilator cycle-count ratio over a matched-arithmetic RVV
baseline. Fitting $C=C_0+C_sN+C_vND$ shows a 16.30$\times$ reduction in the
N-dependent coefficient while preserving the baseline's vector-scaling
behavior. The standalone Scalar SMU maps to 77,103.3 Nangate45 Liberty area
units; the evaluated Full-Offload design point requires 48.8\% more area.
These results show that the specialization boundary inside Online Softmax
Merge matters: specializing the recurrence retains an efficient existing
vector path and avoids adding standalone vector-update capability.
\end{abstract}

\begin{IEEEkeywords}
online Softmax merge, attention, selective offloading, RISC-V vector,

\end{IEEEkeywords}

\section{Introduction}

Tiled and blockwise attention reduce data movement by processing the score
matrix in tiles and maintaining a compact Online Softmax state
\cite{milakov2018online,dao2022flashattention}. After each tile, a merge updates
the running maximum $m$, normalization term $l$, and output vector $O$. This
$(m,l,O)$ state lets the computation preserve exact online-normalization
structure without materializing the complete score matrix.

Online Softmax Merge is not a uniform computation. Its scalar component
updates $m$ and $l$, rescales the old and tile contributions, and generates two
normalization weights. Maximum selection, exponentials, accumulation, and a
reciprocal form a state-dependent chain with little data-level parallelism. Its
vector component then applies the two weights to $O[D]$. Once the weights are
ready, every element in this update is independent and follows the same
multiply-add pattern. We call this split the \emph{recurrence--vector
computational asymmetry}.

The asymmetry exposes an architectural choice between two familiar execution
endpoints. Programmable vector execution preserves flexibility and maps the
regular $O[D]$ update onto existing SIMD resources, but it also executes the
dependency-bound recurrence through general-purpose instructions. Broad
hardware offload specializes the complete merge, including vector work that an
existing vector datapath already handles well. This raises the central
question of this paper: must hardware specialize the complete merge, or can it
isolate the recurrence while retaining the existing vector engine for regular
element-wise work?

We propose a \emph{selective recurrence-offloading architecture}. Its design
principle is to specialize the recurrence while reusing the existing vector
datapath. A Scalar SMU computes the new scalar state and two weights. It commits
these values to a shared scratchpad, after which the vector engine performs the
$O[D]$ update. The shared-memory boundary keeps the recurrence engine narrow
and avoids a second dedicated vector-update path.

We instantiate this architecture on the open-source Spatz RISC-V vector
cluster \cite{spatz2023}. The prototype attaches the Scalar SMU as a
cluster-local engine with an independent tightly coupled data memory (TCDM)
requester. Memory-mapped I/O (MMIO) supplies command and status. Software
starts the recurrence phase, observes completion, and then invokes the
existing RISC-V Vector (RVV) path. The prototype changes neither instruction
decoding nor the RVV datapath.

The measured results connect the architectural partition to its scaling and
hardware consequences. Across three representative model-derived $(N,D)$
shapes, Proposed achieves a 4.53$\times$ geometric-mean cycle-count ratio over
the matched-arithmetic \btor{} baseline. Proposed reduces fitted $C_s$ by
16.30$\times$ and changes fitted $C_v$ by only 6.22\% relative to \btor{}.
The Full-Offload design point lowers $C_s$ further, but its $C_v$ is
3.78$\times$ Proposed and its standalone mapped area is 48.8\% larger. This
paper makes three contributions:

\begin{itemize}
  \item \textbf{Architectural observation and specialization boundary.} We
  identify the recurrence--vector computational asymmetry in Online Softmax
  Merge and use it to define a selective specialization opportunity.

  \item \textbf{Selective recurrence-offloading architecture.} We combine a
  recurrence-only Scalar SMU with an existing vector datapath and exchange
  completed state through a shared scratchpad, avoiding additional dedicated
  vector-update hardware in the proposed design.

  \item \textbf{Prototype and quantitative evaluation.} We implement the
  architecture on Spatz without ISA or RVV datapath changes and compare the
  matched-arithmetic RVV, Proposed, and Full-Offload points using cycle
  scaling, model-shape, FSM, and standalone-area evidence.
\end{itemize}

\section{Background and Motivation}

\subsection{Online Softmax Merge}

Blockwise attention produces a tile-local maximum $m_{\mathrm{tile}}$, a
normalization term $l_{\mathrm{tile}}$, and an output contribution
$O_{\mathrm{tile}}$. The running state contains the corresponding
$m_{\mathrm{old}}$, $l_{\mathrm{old}}$, and $O_{\mathrm{old}}$. One merge row
computes
\begin{align}
m_{\mathrm{new}} &= \max(m_{\mathrm{old}},m_{\mathrm{tile}}),\label{eq:mnew}\\
s_{\mathrm{old}} &= l_{\mathrm{old}}
  \exp(m_{\mathrm{old}}-m_{\mathrm{new}}),\label{eq:sold}\\
s_{\mathrm{tile}} &= l_{\mathrm{tile}}
  \exp(m_{\mathrm{tile}}-m_{\mathrm{new}}),\label{eq:stile}\\
l_{\mathrm{new}} &= s_{\mathrm{old}}+s_{\mathrm{tile}},\label{eq:lnew}\\
w_{\mathrm{old}} &= s_{\mathrm{old}}/l_{\mathrm{new}},\quad
w_{\mathrm{tile}} = s_{\mathrm{tile}}/l_{\mathrm{new}},\label{eq:weights}\\
O_{\mathrm{new}}[j] &= w_{\mathrm{old}}O_{\mathrm{old}}[j]
  +w_{\mathrm{tile}}O_{\mathrm{tile}}[j],\quad 0\leq j<D.
  \label{eq:vector-update}
\end{align}
Equations~\eqref{eq:mnew}--\eqref{eq:weights} produce the updated scalar state
and two weights. Equation~\eqref{eq:vector-update} applies the weights across
the output dimension.

\subsection{Recurrence--Vector Computational Asymmetry}

The scalar equations form a dependency chain. The maximum determines both
exponential arguments. The scaled lengths determine $l_{\mathrm{new}}$, and
$l_{\mathrm{new}}$ determines the reciprocal used by both weights. The chain
combines control-sensitive maximum selection with nonlinear exponential and
reciprocal operations. It performs little work per state update, but each step
depends on values produced earlier in the same row.

The vector equation has the opposite structure. After weight generation,
$O_{\mathrm{new}}[j]$ has no dependence on
$O_{\mathrm{new}}[j']$ for $j\neq j'$. Every element executes regular
multiply-add arithmetic with unit-stride vector accesses. Its work scales as
$O[D]$ and matches a vector load/store and arithmetic pipeline. Figure~\ref{fig:motivation}
summarizes this computational split.

\centering
\includegraphics[width=\textwidth]{../../experiments/plots/figure1_computation_decomposition.pdf}
\caption{\textbf{Online Softmax Merge contains a dependency-bound recurrence
and a data-parallel vector update.} The scalar chain produces two weights;
the ready weights expose independent multiply-add work across $D$ elements.}
\label{fig:motivation}
\end{figure*}

\subsection{Execution Alternatives and Specialization Boundary}

Programmable execution maps the vector phase efficiently when a processor
already provides vector loads, stores, and arithmetic. The same route retains
the scalar recurrence in software, where dependency, control, and nonlinear
operations limit useful vectorization. The matched-arithmetic \btor{} baseline
in this paper represents this endpoint: software executes the recurrence, and
RVV executes the output update.

Full offload places both phases in dedicated hardware. This endpoint can
specialize the recurrence and integrate the complete merge behind one command.
It also builds standalone vector-update capability alongside an existing
vector engine. Our Full-Offload design point represents this alternative. The
computational asymmetry suggests an intermediate boundary that dedicates
hardware to the recurrence and preserves the vector phase on the existing
datapath.

\section{Selective Recurrence-Offloading Architecture}

\subsection{Architecture Overview}

Selective recurrence offloading separates the merge at the point where the
weights become ready. Figure~\ref{fig:selective-architecture} shows four
platform-independent components: a control plane, a recurrence engine, an
existing vector datapath, and a shared scratchpad. The Scalar SMU is the only
new compute engine. The architecture retains the vector datapath and its
memory path.

\begin{figure*}[t]
\centering
\includegraphics[width=\textwidth]{../../experiments/plots/figure2_selective_architecture.pdf}
\caption{\textbf{Selective recurrence offloading adds a narrow recurrence
engine and reuses the existing vector datapath.} Shared scratchpad state forms
the phase boundary and removes the need for a separate vector-update path.}
\label{fig:selective-architecture}
\end{figure*}

\subsection{Execution Partition}

The Scalar SMU executes Eqs.~\eqref{eq:mnew}--\eqref{eq:weights}. This
partition places maximum selection, two exponential rescalings, length
accumulation, reciprocal normalization, and weight generation in a short
scalar datapath. The engine accepts one or more independent merge rows and
produces $m_{\mathrm{new}}$, $l_{\mathrm{new}}$,
$w_{\mathrm{old}}$, and $w_{\mathrm{tile}}$ for each row.

The existing vector engine executes Eq.~\eqref{eq:vector-update}. It loads the
two output vectors and the completed weights, performs the element-wise
multiply-add sequence, and stores $O_{\mathrm{new}}$. This assignment keeps
the $O[D]$ work on the datapath whose width, memory interfaces, and arithmetic
lanes already target regular data parallelism.

\subsection{Shared-State Handoff and Execution Sequence}

The architecture uses shared scratchpad state to decouple the two phases. The
control plane first makes the old and tile recurrence state visible to the
Scalar SMU. The engine reads that state, computes the recurrence, and commits
the new state and two weights. Completion establishes that the shared values
are ready. The control plane then invokes the vector phase, which consumes the
weights and updates $O[D]$.

This handoff keeps the two engines independent at the datapath level. It does
not require a private Scalar-SMU-to-vector bypass or a second vector register
interface. The shared scratchpad also exposes the state to software and lets
the implementation reuse its normal memory arbitration. Platform-specific
command registers, requester ports, and memory names belong to the prototype
and appear in Section~V.

\section{Scalar SMU Microarchitecture}

\subsection{Scalar Datapath}

The Scalar SMU follows the recurrence dependencies directly. Figure~\ref{fig:smu-datapath}
maps the implemented RTL dataflow. A comparator selects $m_{\mathrm{new}}$,
and two subtractors form the old and tile deltas. Two distinct EXP LUT paths
evaluate the rescaling factors in parallel. Two multipliers scale
$l_{\mathrm{old}}$ and $l_{\mathrm{tile}}$, and an adder forms
$l_{\mathrm{new}}$. The implementation registers the scaled lengths and
$l_{\mathrm{new}}$ before the next FSM state. A single reciprocal path then
feeds two weight multipliers to produce $w_{\mathrm{old}}$ and
$w_{\mathrm{tile}}$.

\begin{figure*}[t]
\centering
\includegraphics[width=\textwidth]{../../experiments/plots/figure3_scalar_smu_datapath.pdf}
\caption{\textbf{The Scalar SMU mirrors the recurrence dependency chain.}
Two EXP paths operate in parallel; registered $l_{\mathrm{new}}$ then enters
one reciprocal path that generates both normalized weights.}
\label{fig:smu-datapath}
\end{figure*}

The RTL receives and writes FP32 values at the scratchpad interface. Internal
helpers convert maxima and lengths to signed or unsigned 48-bit fixed point
with 32 fractional bits. EXP and reciprocal LUT outputs use Q1.23. The two
length-scaling products, $l_{\mathrm{new}}$, and the weights use the 48-bit
Q16.32 representation before conversion back to FP32 for writeback. The Scalar
SMU contains no $O[D]$ datapath in the proposed scalar-only configuration.

\subsection{EXP and Reciprocal Approximation}

The EXP block implements a 257-entry LUT over the supported interval
$[-8,0]$ with linear interpolation. Non-positive inputs inside the interval
produce a Q1.23 factor; values below $-8$ saturate to zero, and positive values
saturate to one. Online Softmax Merge produces non-positive deltas because
$m_{\mathrm{new}}$ is the maximum of the two inputs.

The reciprocal block uses a 257-entry mantissa LUT with linear interpolation.
It returns a Q1.23 mantissa and a signed exponent adjustment derived from the
FP32 exponent of $l_{\mathrm{new}}$. The weight multipliers apply this scaled
reciprocal to the two registered lengths. This structure implements the
arithmetic used by the RTL and by the matched software reference in the
evaluation.

\subsection{Controller and Execution Schedule}

The scalar-only controller uses a four-state sequence. \texttt{LOAD\_SCALAR}
issues four scalar scratchpad reads. \texttt{COMPUTE\_SCALAR} evaluates the
maximum, EXP paths, and length update. \texttt{COMPUTE\_WEIGHT} evaluates the
reciprocal and weight generation. \texttt{STORE\_SCALAR} writes the new
maximum, new length, and two weights. Scalar-only execution then advances to
the next row or completion; it skips the RTL's Full-Offload
\texttt{UPDATE\_VECTOR} state.

\begin{figure}[t]
\centering
\includegraphics[width=\columnwidth]{../../experiments/plots/figure4_smu_schedule.pdf}
\caption{\textbf{The nominal scalar-only FSM requires 24 busy cycles per
row:} 13 load, one scalar-compute, one weight-compute, and nine store cycles.
The timeline assumes no TCDM stalls.}
\label{fig:smu-schedule}
\end{figure}

RTL observer counts give the nominal no-stall schedule in
Figure~\ref{fig:smu-schedule}: $13+1+1+9=24$ busy cycles per row. TCDM
handshakes account for 22 cycles, while the two combinational compute stages
account for one cycle each. Model-shape observers record 289, 769, and 962
busy cycles for the BERT, Mistral, and Qwen2.5-14B-Instruct shapes, adding one
or two wait cycles to $24N$. The schedule describes the SMU busy interval; the
measured kernel cycles also include software command and completion handling
and the later RVV phase.

\section{Spatz-Based Prototype Integration}

\subsection{Relevant Spatz Cluster Organization}

Spatz supplies the vector resources that selective recurrence offloading
reuses \cite{spatz2023}. The evaluated default cluster contains two
Snitch--Spatz core complexes and a shared 128-KiB, 16-bank TCDM. Each Spatz
vector unit provides a vector arithmetic unit and a vector load/store unit
(VLSU) connected to TCDM. The prototype keeps these vector units and their
existing TCDM ports unchanged.

\subsection{SMU Attachment and TCDM Interface}

Figure~\ref{fig:spatz-integration}a shows the concrete attachment. The cluster
peripheral holds the command, buffer offsets, dimensions, mode, and status
fields. It drives the Scalar SMU's control interface. The SMU adds one
independent TCDM requester to the cluster interconnect, alongside the existing
core, RVV, and system requesters. This requester performs the scalar reads and
writes described in Section~IV.

\begin{figure*}[t]
\centering
\includegraphics[width=\textwidth]{../../experiments/plots/figure5_spatz_integration.pdf}
\caption{\textbf{Spatz instantiates selective recurrence offloading through
its existing peripheral and shared-memory structure.} (a) The Scalar SMU adds
an MMIO-controlled TCDM requester; RVV retains its ports. (b) Completion and
shared weights sequence the recurrence and vector phases.}
\label{fig:spatz-integration}
\end{figure*}

The Scalar SMU reads FP32 arrays for $m_{\mathrm{old}}$,
$l_{\mathrm{old}}$, $m_{\mathrm{tile}}$, and $l_{\mathrm{tile}}$. It writes
arrays for $m_{\mathrm{new}}$, $l_{\mathrm{new}}$,
$w_{\mathrm{old}}$, and $w_{\mathrm{tile}}$. The shared TCDM indexes rows
consistently across these arrays. The interconnect arbitrates the requester
with the existing memory ports, so the design needs no dedicated physical
link from the SMU to Spatz.

\subsection{MMIO Control and Software--Hardware Execution Flow}

Software programs TCDM offsets, $N$, $D$, stride, and scalar-only mode through
MMIO, clears prior completion state, and asserts start. It then polls the
busy, done, and error status bits. On completion, the new scalar state and
weights already reside in TCDM. Software loads the two weight arrays and calls
the existing RVV kernel for each $O[D]$ row. Figure~\ref{fig:spatz-integration}b
shows this sequence.

The integration preserves the architectural boundary in a concrete cluster.
The Scalar SMU communicates through MMIO and shared TCDM, while the vector
phase uses normal RVV instructions and memory accesses. The implementation
adds no instruction and changes no RVV arithmetic, load/store, or register
path.

\section{Evaluation}

The evaluation asks four architectural questions. Does selective offloading
remove the recurrence-related scaling cost? What cycle-count ratios result at
representative merge dimensions? What standalone hardware does recurrence
specialization require? How does the selected boundary compare with full
offload?

\subsection{Methodology and Baselines}

We evaluate FP32 merge kernels with arrays resident in the default Spatz
TCDM. The active matrix contains 26 deterministic cases, three configurations,
and three independent simulator runs, for 234 records. Each run measures one
logical query-position merge in RTL/Verilator. The matched software reference
uses the same EXP and reciprocal LUT arithmetic as the RTL. All records pass a
scale-aware $10^{-3}$ functional check, contain finite outputs, and reproduce
the same cycle count across the three runs.

The comparison contains three execution points. \btor{} executes the scalar
recurrence in matched-arithmetic software and the vector update on existing
RVV. Proposed executes the recurrence in the Scalar SMU and retains the same
RVV vector update. Full-Offload executes both phases in the dedicated engine.
We report cycle-count ratio as \btor{} measured cycles divided by design
measured cycles, without a frequency conversion.

The model-derived rows use deterministic generated states and dimensions from
BERT, Mistral-7B, and Qwen2.5-14B-Instruct configurations. They represent one
attention position across all query heads. $N$ is the query-head count, and
$D$ is hidden width per query head. Grouped-query attention therefore uses
query heads for $N$. Standalone hardware results use Yosys/ABC and Nangate45.
The area flow reports mapped cells and Liberty cell-area units. A separate
pre-layout register-to-register timing flow provides a combinational-delay
proxy; the available flow does not define a synchronous $F_{\max}$ or cluster
PPA result.

\subsection{Recurrence and Vector Scaling Decomposition}

We fit the measured cycles for each design to
\begin{equation}
C(N,D)=C_0+C_sN+C_vND
\label{eq:scaling-model}
\end{equation}
using 23 measured $(N,D)$ shapes. $C_s$ captures the N-dependent,
recurrence-related scaling component in cycles per row. $C_v$ captures the
ND-dependent, vector-related component in cycles per element. $C_0$ is the
fitted intercept and includes fixed effects in this implementation. The three
fits have $R^2$ values between 0.99928 and 0.99999.

\begin{figure*}[t]
\centering
\includegraphics[width=\textwidth]{../../experiments/plots/figure2_scaling.pdf}
\caption{\textbf{Selective recurrence offloading changes the N-dependent
scaling component and retains the RVV-like ND-dependent component.} The bars
show fitted $C_s$ and $C_v$ from 23 measured RTL/Verilator shapes per design.}
\label{fig:scaling-decomposition}
\end{figure*}

Figure~\ref{fig:scaling-decomposition} shows the fitted coefficients. For
\btor{}, $C_0=161.353823$, $C_s=1471.818713$, and $C_v=2.267063$. For
Proposed, $C_0=1382.770246$, $C_s=90.278155$, and $C_v=2.126010$. Proposed
therefore reduces $C_s$ by 16.30$\times$, while its $C_v$ is 6.22\% lower than
\btor{}. This combination
matches the intended partition: hardware removes most recurrence-related
cycle growth, and the reused RVV path continues to determine vector scaling.

For Full-Offload, $C_0=1285.577085$, $C_s=19.317262$, and $C_v=8.029465$.
Its lower $C_s$ shows that broader specialization reduces the remaining
row-dependent term. Its $C_v$ is 3.78$\times$ Proposed, placing a larger
per-element cost on the design point that replaces the existing RVV update.
The scaling result identifies the architectural effect of the boundary:
Proposed combines a hardware-like recurrence term with an RVV-like vector
term.

\section{Related Work}

Programmable and vectorized Softmax implementations keep most computation on
the processor side. Titopoulos et al. vectorize FlashAttention with standard
RVV instructions \cite{titopoulos2026vectorized}, and Lai et al. use RVV
intrinsics for Softmax \cite{lai2026rvvsoftmax}. VFA changes the
FlashAttention schedule through global-maximum pre-computation to reduce
vector work \cite{sun2026vfa}. These approaches preserve programmability and
vector reuse. Our architecture retains that vector endpoint while moving the
state-dependent merge recurrence to dedicated hardware.

ISA and operator-level acceleration place specialization inside the
programmable path. VEXP adds scalar and SIMD exponential operations to RISC-V
\cite{vexp2025}. Alexandridis et al. fuse exponential and multiplication
operators for FlashAttention hardware \cite{alexandridis2025expmul}. These
designs accelerate selected arithmetic operations. Selective recurrence
offloading instead treats the complete dependency-bound recurrence as the
unit of specialization and leaves the vector ISA unchanged.

Dedicated Softmax accelerators choose a broader boundary. Softermax combines
unnormalized and normalization hardware \cite{softermax2021}. TEA-S implements
a compact PLAC-based Softmax architecture \cite{teas2023}. SoftEx attaches a
Softmax/GELU hardware processing engine to shared TCDM \cite{softex2025}, and
Fairoose and Mishra implement parallel online normalization inside a Softmax
accelerator \cite{fairoose2026parallel}. These systems demonstrate several
useful points on the dedicated-normalization spectrum. Their specialization
scope includes broader Softmax computation than the blockwise recurrence
isolated here.

Full-attention accelerators extend specialization across normalization,
output production, and surrounding attention operators. Such integration can
remove software coordination and exploit operator fusion. It also places the
output-vector path within dedicated hardware. The Full-Offload point in our
evaluation captures this direction at the merge-kernel level.

Selective recurrence offloading lies between fully programmable vector
execution and broad accelerator offload. It specializes the dependency-bound
state transition, communicates completed state through a shared scratchpad,
and reuses an existing vector datapath for the regular $O[D]$ phase. The Spatz
prototype demonstrates this position without defining the architecture around
a specific cluster interface.

\section{Conclusion}

Online Softmax Merge combines heterogeneous scalar and vector phases. The
maximum, exponential rescaling, normalization accumulation, and weight
generation form a dependency-bound recurrence. The $O[D]$ update becomes
regular data-parallel work once the two weights are ready. Selective recurrence
offloading uses this asymmetry to place only the recurrence in a Scalar SMU
and retain the existing vector datapath.

The Spatz prototype implements this partition through MMIO control and a
shared-TCDM handoff without modifying the ISA or RVV datapath. The measured
scaling evidence shows a 16.30$\times$ reduction in the recurrence-related
$C_s$ term while preserving the RVV-like $C_v$ term. Model-derived shapes
reach a 4.53$\times$ geometric-mean cycle-count ratio over \btor{}. Compared
with the Full-Offload point, Proposed also avoids the larger vector coefficient
and 48.8\% additional standalone mapped area. These results establish
selective recurrence offloading as a meaningful execution boundary for the
evaluated Online Softmax Merge kernel.
